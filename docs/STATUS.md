# Mosaic の実装状況

更新: 2026-09-12

Codexはログイン済みのローカルCLIを通じて `gpt-6-astra` / `xhigh` を呼び出す。個人のCLI設定の読み込みを無効にし、生成中のシェルはネットワークアクセス禁止・基本環境変数のみ継承とする。公開リポジトリの保護と運用上の境界は [SECURITY.md](../SECURITY.md) を参照。

## サービスとゲーミフィケーション

- 1つのアプリでゲーム／サービス／ゲーミフィケーションを切り替える。種類ごとの下書きと生成形式を保存し、再起動でも復元する。
- サービスは10カテゴリ・60項目。利用者と困りごと、中心行動、SNSの必要性、利用フロー、検証方法を設計する。HTMLまたはAvaloniaで生成する。
- ゲーミフィケーションはゲーム163項目＋領域・行動・ゲームとの対応・比較検証26項目。ゲームなしの通常モードとの比較を生成指示に含める。
- 「アイデアを探す」にサービス5案、ゲーミフィケーション4案、ゲーム1案を用意。内蔵の未検証の仮説を編集可能な企画の出発点として採用できる。
- 3種類とも、ローカルGPT-6 xhighで生成し、履歴の「モックの感想」から別フォルダに改善版を作れる。改善は履歴のKind・Formatを固定する。
- サービスとゲーミフィケーションはexperiment.mdも必須。改善前の資料をbaselineへ分離し、新しい補完企画・完了レポート・検証メモを要求する。
- 企画・セッションはVersion 2。Version 1をゲームへ移行し、旧企画の未知キー・履歴・感想を保持する。旧アプリでVersion 2は読めない。
- 実モデルで189項目と検証メモの最終確認が20分を超えたため、実行上限を30分に調整。時間切れは未完了とし、途中の成果物を保持する。自動再試行はしない。
- 既存の生成失敗通知順、コピー制限、秘密ファイル除外、自動保存・Recoveryを維持する。

仕様は [企画モード](planning-modes.md)、実行した検証と未確認事項は [検証記録](verification.md) を参照。

## 保存と成果物の扱い

- セッションはOSのLocalApplicationData内の `GameMockStudio/session.json`。CLIの認証情報は保存しない。
- 自動保存は1つの作業画面を次回起動へ引き継ぐ。共有ファイルの複数ウィンドウ同時編集は想定しない。
- 破損セッションは `session-unreadable-日時-ID.json` として残す。
- 新規作成・読み込み前の企画は `Recovery/brief-日時-ID.json` に残す。自動削除しない。
- 履歴の上限は20件。感想の下書きも履歴に保存する。履歴から外れても生成ファイルと適用済みの感想は削除しない。
- 改善版の履歴は元フォルダと適用した感想を保持する。次の感想は空欄から始まり、元の版の下書きは残す。
- 異常終了時に生成中だった履歴は「中断」として復元する。自動再生成しない。
- 手動JSON保存は別名の明示的なエクスポート。自動保存から手動保存ファイルを上書きしない。
- 完了レポートは実装側の申告を検査するもので、コンパイル・ゲームのプレイ成功を保証しない。

## 今回の範囲外

ブラウザ形式を実用確認の主対象にしている。Unity/Avalonia生成物の自動ビルド・自動プレイ、元の生成物への直接上書き、複数PC間の同期は未実装。これらは実行環境や編集・同期の競合方針を追加で設計する必要があり、現在の「新規・改善とも別フォルダへ生成する」機能には含めない。モデルと推論強度は元の指定どおり固定する。
