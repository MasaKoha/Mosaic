# Game Mock Studio の実装状況

更新: 2026-09-12

Codexはログイン済みのローカルCLIを通じて `gpt-6-astra` / `xhigh` を呼び出す。個人のCLI設定の読み込みを無効にし、生成中のシェルはネットワークアクセス禁止・基本環境変数のみ継承とする。公開リポジトリの保護と運用上の境界は [SECURITY.md](../SECURITY.md) を参照。

## 今回の洗い出しと対応

| 課題 | 対応 |
|---|---|
| CLIが即座に失敗すると開始通知がUIへ届かず、失敗履歴が残らない | 終端通知をMaterializeしてUIへ順序どおり配送し、失敗前の開始記録を保持 |
| 遊んだ感想を既存ゲームへ反映できない | 「ゲームの感想」タブ、ゲーム別下書き、コピーした実装への改善指示を追加 |
| 改善時に元のゲームを上書きする恐れがある | 別フォルダへの制限、リンク拒否、秘密ファイル・キャッシュ除外、件数・容量制限を追加 |
| 過去の完了ファイルを改善の成功と誤認する | 改善前の資料をbaselineへ分離し、今回の企画と完了レポートを必須化 |
| 終了すると未保存の企画が消える | 入力停止700ms後の自動保存、終了時の最終保存、再起動時の復元を追加 |
| CLIの場所と出力先が再起動で戻る | 企画と同じセッションへ保存 |
| 過去の生成結果へ戻れない | 最近20件の履歴、成果物フォルダ・ゲームを開く操作を追加 |
| AIが補完した企画を再利用する手順が長い | 履歴から「補完済み企画で編集する」。取り込み前の企画を退避 |
| 退避ファイルを見つけにくい | 「退避した企画を探す」ボタンを追加 |
| 破損した自動保存で起動・終了が行き詰まる | 原本を別名で退避。読取権限エラーでも編集と手動保存を利用可能にし、終了時の選択肢を用意 |
| 保存失敗時に最新入力を失う | 原子的な置換と書き込み直列化。終了時の失敗は編集へ戻るか明示的に未保存終了を選択 |
| 退避待ち中に追加入力すると消える | 企画の置換中は入力を無効化。終了は進行中のファイル操作を待つ |
| 未知の企画項目が読込・保存で消える | 未知キーを保持してプロンプト・保存へ引き継ぎ、生成結果でも明示指定を照合 |
| 未完了でもファイルが揃うと成功になる | generation-report.json の完了状態と阻害事項を検査 |
| 空白だけの文書や空のC#ファイルを成果物と認める | 空白のみの必須文書と空ソースを拒否 |
| 複数エラーで最初の失敗原因が失われる | 最初のCLI失敗を維持 |
| 生成が無期限に待機する | CLI実行開始から20分で子孫プロセスを停止し、時間切れを失敗として通知 |
| プロセス終了・大量ログ・取消が未検証 | 偽CLIの実プロセステストで標準入出力・異常終了・子孫停止を検証 |
| 非同期完了がUIスレッドへ戻らない | 起動・操作・保存・終了のRx購読をUIスケジューラへ接続 |
| Macで起動コマンドが必要 | 自己完結の .app を生成する tools/package-macos.sh を追加 |
| Avalonia 12で非推奨APIの警告が出る | WatermarkをPlaceholderTextへ更新 |

## 保存と成果物の扱い

- セッションはOSのLocalApplicationData内の `GameMockStudio/session.json`。CLIの認証情報は保存しない。
- 自動保存は1つの作業画面を次回起動へ引き継ぐ。共有ファイルの複数ウィンドウ同時編集は想定しない。
- 破損セッションは `session-unreadable-日時-ID.json` として残す。
- 新規作成・読み込み前の企画は `Recovery/brief-日時-ID.json` に残す。自動削除しない。
- 履歴の上限は20件。感想の下書きも履歴に保存する。履歴から外れても生成ファイルと適用済みの感想は削除しない。
- 改善版の履歴は元フォルダと適用した感想を保持する。次の感想は空欄から始まり、元の版の下書きは残す。
- 異常終了時に生成中だった履歴は「中断」として復元する。自動再生成しない。
- 手動JSON保存は別名の明示的なエクスポート。自動保存から手動保存ファイルを上書きしない。
- 完了レポートは実装側の申告を検査するもので、コンパイル・ゲームのプレイ成功を保証しない。

## 今回の範囲外

ブラウザ形式を実用確認の主対象にしている。Unity/Avalonia生成物の自動ビルド・自動プレイ、元の生成物への直接上書き、複数PC間の同期は未実装。これらは実行環境や編集・同期の競合方針を追加で設計する必要があり、現在の「新規・改善とも別フォルダへ生成する」機能には含めない。モデルと推論強度は元の指定どおり固定する。
